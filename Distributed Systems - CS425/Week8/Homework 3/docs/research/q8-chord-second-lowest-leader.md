  The data center onboard (with hundreds of machines) uses a ring-based DHT (among the machines) with a Chord-like routing algorithm, with each peer maintaining one successor and one predecessor, and Chord finger tables.   iv. Briefly discuss what might happen if failures occur during the election run, while finger table entries were not updated to reflect the failures.

# Elect the second-lowest Chord ID with one routing request

## Answer

**i. Protocol.** Identifiers are m-bit integers on a circle modulo 2^m. Every participant runs the same local rule, using only the successor pointer it already stores. A node M whose successor has a smaller ID than M is the unique maximum ID; that successor L is the unique minimum ID. M initiates one Chord end-to-end routing request: route from M to ring ID (L.id + 1) mod 2^m, with payload “you are the leader.” Every other participant initiates nothing. The node to which Chord delivers that route becomes the leader and every other node stays a non-leader.

That delivery is the second-lowest ID. Clockwise order from the minimum is increasing ID order, so L’s immediate successor is the second-smallest ID. The ring ID L+1 has no identifier strictly between it and L, so the first peer at or clockwise of L+1 is exactly L’s successor. For N ≥ 2 and distinct IDs, the minimum is not 2^m − 1, so L+1 does not wrap.

**ii. Safety and liveness, assuming correct successors and fingers and no failures.** Safety: a single correct successor cycle has exactly one edge from a higher ID to a lower ID, so exactly one node sends the leader route, and Chord’s successor map delivers it to exactly one node, the second-lowest. Liveness: the local test does no I/O, and one lookup with correct fingers and successors reaches the responsible node and stops. The recipient then sets its leader flag.

**iii. Cost.** One Chord lookup. Completion time is O(log N) hops, which is O(1) end-to-end routing requests issued in series. The lookup contacts O(log N) nodes, so the hop-message count is O(log N). Initiations are O(1) per participant (one node initiates one request; the rest initiate zero). Writing H for the cost of one Chord lookup, H = O(log N), time is O(H), and messages are O(H).

**iv. Failures with stale fingers.** This deployment keeps one successor, so it does not have the successor list of length r = Θ(log N) that Chord uses to route around failures. The election message is an ordinary lookup of ring ID L+1. If successor pointers are still correct and the stale fingers name live nodes, Chord still returns the true successor, and the lookup can slow from O(log N) toward a walk along successors; the leader is still the second-lowest, and the O(log N) bound is what is lost. If a hop’s finger or the single successor still names a failed peer, there is no alternate successor to substitute. The course’s failure picture is that the lookup fails. The ToN failure example is sharper: a node that no longer knows the true successor returns the next live finger it does know, which can be a later peer. Then either nobody receives the payload (liveness fails) or a live peer other than the second-lowest is told it is leader (safety fails). The same split applies if the maximum dies before it sends, or if the second-lowest itself is the failed node and successors have not been repaired. Fall 2026 stabilization is what refreshes a finger by routing to (n + 2^i) mod 2^m and what the slides credit for non-loopiness and eventual lookup success; the problem states that this refresh has not been applied to the fingers.

## Recommendation

Use the one-route protocol in the Answer. It is the shortest algorithm that stays inside the allowed message type: the maximum recognizes itself from the successor wrap, and one route to (minimum + 1) mod 2^m is delivered to the second-lowest. Report completion time O(log N) and hop messages O(log N), and state that this is a single end-to-end routing request so the per-participant initiation bound holds. For part (iv), separate the two Chord cases: stale live fingers with a correct successor (still correct, possibly linear), versus a dead finger or a dead single successor with no r-list (lookup fails, or returns a later live peer). The tradeoff is message count against how obvious the “who starts” rule is. Having every peer route to ring ID 0, then having the minimum route to its own ID + 1, is also correct and easier to see if a reader forgets the wrap test, and it costs O(N) initiations and O(N log N) hop messages.

## Ruled out

- Walking the leader decision around the successor ring, as in the ring election of problem 6. Those are neighbor messages, and the problem allows only end-to-end routes to a ring ID. On a correct ring that walk is also Θ(N) hops.
- Every peer routing to ring ID 0 so the minimum learns it is the minimum and then routes to (its ID + 1) mod 2^m. Successor(0) is the minimum, and the second route hits the second-lowest. Each participant still initiates O(1) routes. The hop count is O(N log N) because N lookups run, so it is not the fewest-message algorithm. It remains a correct fallback if the wrap test is disallowed.
- Routing to ring ID 2^m − 1 in order to find the maximum. Successor(2^m − 1) is the minimum whenever no peer sits on that ID, because the clockwise successor wraps.
- Reading the second-lowest off a predecessor list. The minimum’s predecessor is the maximum. The second-lowest is the minimum’s successor. The homework gives one predecessor, so a length-2 predecessor list is not available. An older wording of this story asked for the second-highest ID and mentioned three predecessors; that wording is not problem 8 of hw3.fa26.pdf, and the paywalled writeup found in search was not used.
- Treating the r = 2 log(N) successor list, or ToN/SIGCOMM’s r = Ω(log N) list, as part of this system. Problem 8 states one successor and one predecessor. Those lists are what make lookups survive failed fingers; their absence is the part (iv) point.
