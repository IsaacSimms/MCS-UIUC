# Lecture Breakdown Style Guide

Produce a structured breakdown of the given lecture for personal notes. Match prior CS 410 summaries: plain English first, then technical precision; high-signal, no fluff. Headings may adapt to the lecture type (motivation, methods, evaluation, etc.).

## Required Structure

**Lecture number and title** (course context / matching lecture if known)

### TLDR
One short paragraph stating the core idea.

### Key sections and what to retain
Break into 3–5 major points. For each:
- Open with a one-sentence everyday explanation.
- Then the course concept, definitions, and any central formula (inline).
- Mark the essential takeaway with **Retain**.
- Add a light “builds on X” pointer only when it clarifies.
- Include a short example or metaphor only if the lecture supplies one or if it is clearly high-signal for retention; otherwise omit.

### Recap (core ideas to keep)
Short bullet list of the essential takeaways.

## Style Rules
- Always start each section with plain English, then technical detail. Stay precise after the opener.
- Prefer short paragraphs and clear bullets.
- Define terms in context.
- Highlight the key conceptual distinction or design choice.
- Keep the note self-contained.
- Only mention failure modes the lecture itself emphasizes.
- Add a one-line forward pointer only if the lecture itself indicates what comes next.
- Output pure markdown suitable for taking notes from.
